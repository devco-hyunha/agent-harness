# delegation-brief (서브에이전트 요청 규격)

## 원칙
서브는 대화 맥락을 보지 못한다. 구현·보정 위임은 요청을 두 경로로 전달한다.
- (a) 작업 문서 파일
- (b) 자체 포함 프롬프트 (프롬프트만 읽어도 작업할 수 있어야 한다)

작업 문서 파일은 구현·보정 위임에만 필수다. 읽기·검색·기록·확인·리뷰 서브는 자체 포함 프롬프트만 쓴다.

## 위임용 작업 문서 필수 섹션
기획용 작업 문서(plan-harness)와 다른 문서이며, 기획용 문서를 바탕으로 만든다.
목적 / 서브 보고에서 채택한 근거(출처 포함) / 작업 범위 / 금지 사항 / 산출물 / 검증 방법 / 보고 형식.
저장 위치: 프로젝트에 정해진 위치가 있으면 그곳, 없으면 기획용 작업 문서 옆에 docs/tasks/<순번>-<작업명>.brief-<번호>.md
금지 사항에는 범위 밖 파일 수정·생성 금지, 커밋·푸시 금지, 검증 인라인(-c) 실행(임시 스크립트 파일 금지), 임의 코드 샘플 금지를 포함한다.
보정 작업이면 "변경하지 않는 것"을 추가한다.

## 프롬프트 필수 항목
- 작업 문서 절대 경로(구현·보정 위임일 때)
- 목적과 범위 요약
- 금지 사항
- 산출물
- 검증 명령
- 보고 형식
- 참고 문서 경로
- 프로젝트 규칙 문서 경로(있으면)

## 프롬프트 공통 지시 4개
1. 쓰기 작업 서브는 작업 문서(없으면 프롬프트)와 거기에 적힌 파일만 읽은 직후 바로 작성·수정한다. 그 밖의 탐색은 하지 않는다. 읽기 전용 서브에는 적용하지 않는다.
2. 도구 호출 문법을 본문 텍스트로 쓰지 않는다.
3. 모든 보고는 사용자가 쓰는 언어로, 정중한 존댓말을 유지한다.
4. 실패하면 즉시 멈추고 실패 원인과 현재 파일 상태를 보고한다.

공통 지시 4개와 별도로, 프롬프트에 다음 두 줄도 넣는다.
- 원문 유지 원칙은 하네스 문서 1절을 따른다.
- 프로젝트 규칙 우선은 하네스 문서 1절을, 승인·안전 규칙은 하네스 문서 5절을 따른다. (하네스 문서: harness/HARNESS.md)

## 모델 선택
모델 선택은 하네스 문서 8절을 따른다.

## 보고 검증
서브 보고는 확인 전용 서브가 확인하고 메인이 판단하는 것을 전제로 한다.

## 이스케이프
긴 프롬프트를 JSON 등 구조화 도구에 넣을 때는 해당 이스케이프 규칙을 따른다. 서브에이전트 호출 방식이 일반 문자열이면 해당 없다.
프로젝트 규칙 우선은 하네스 문서 1절을, 승인·안전 규칙은 하네스 문서 5절을 따른다. (하네스 문서: harness/HARNESS.md)
